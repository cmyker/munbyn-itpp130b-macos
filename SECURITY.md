# Security and privacy

Experimental local printing software. Report security issues through the repository's GitHub private vulnerability reporting if enabled; otherwise open an issue describing only the category, without labels, device IDs, credentials or exploit payloads containing private data. There is no telemetry or external service in the app.

The print listener binds exactly `127.0.0.1:19100`, never a wildcard/LAN address. Queue sharing is disabled. **Loopback is not authentication:** any local process can submit raster jobs, fill the bounded spool or, once BLE printing is enabled, cause selected-printer output. Browser/network isolation is not an authorization guarantee. This alpha is appropriate only on a trusted single-user machine. A local process able to change the user's files or run as that user can control the bridge. Raw TCP has unacknowledged handoff windows documented in ADR-001.

Control uses an owner-only AF_UNIX socket and checks `getpeereid` against the app UID. No administrative command is accepted by the print TCP listener. Queue installation uses fixed `/usr/sbin/lpadmin` with an argument vector, a fixed queue name/URI, ownership checks and Apple's Authorization Services; it never constructs a privileged shell command. Legacy AuthorizationExecuteWithPrivileges is deprecated and is a packaging/platform compatibility limitation; no privileged daemon/helper is installed.

Raster input uses Apple's cupsRaster API with a bounded C read callback. Compressed/unsupported variants are rejected before decoder allocations. Limits: 64 MiB raw input, 60 seconds per receive, 32 source pages/64 expanded labels, 832 × 1300 dots maximum, exact supported media/resolution and strict row lengths. One connection is parsed at a time, backlog two. Control input is at most 4096 bytes (wire hard cap 16 KiB), with a five-second receive timeout; operations have a bounded response wait. Administrative prompts may outlive the CLI response timeout: check state before repeating a queue operation.

Private directories/files reject symlink roots, enforce current-user ownership and 0700/0600 permissions. Atomic payload/state writes use fsync and rename. These protect ordinary other-user access, not malicious same-user code or a compromised OS. Incoming job contents never enter diagnostic status. Dry-run PBM/TSPL files are visibly sensitive and excluded from git; capture retention is explicit, capped at 32 folders/128 MiB. Finished print payload is deleted; terminal metadata expires at 14 days/64 entries. Pending and unknown jobs are never silently expired. Ordinary deletion does not promise secure erasure on an SSD.

CI uses read-only repository permissions and no release secrets. Pull requests do not get signing/notarization credentials. Do not put GitHub tokens, Bluetooth identifiers, real labels, private names/addresses or diagnostics in issues, commits or Actions logs. Only synthetic fixtures may be published.
